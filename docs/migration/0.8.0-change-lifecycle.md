# Migrating to 0.8.0

Version 0.8.0 retains the Cursor-only, context-preserving boundary and all 0.7 command names and adds `/curiosity-spec`, `/curiosity-ledger`, `/curiosity-implement`, and `/curiosity-close`. Verify exactly four agents, five skills, twelve commands, and one always-applied rule in a separate Cursor session.

Every command now publishes a structured semantic route contract. Terminal precedence is `BLOCKED_ROUTING` (Task/agent/skill routing only), `BLOCKED_AUTHORITY` (successfully routed action beyond grant), `USER_DECISION_REQUIRED` (consequential owner choice), `BLOCKED_EVIDENCE` (mandatory evidence failure), then `DONE` (all criteria and gates).

Every writable branch now invokes the spec phase automatically. It displays a revisioned intent/acceptance contract, uses model-steered AskQuestion when the host exposes it, persists exact approval as a new immutable `openspec/changes/<change-id>-rNNNN/` package, and keeps persistence plus mutation in the same sole implementer Task. Existing manually authored packages are compatibility inputs, not write authority. Focused checks no longer substitute for every available repository-declared full check. No data migration runs automatically; new immutable revisions are created only for approved future writes.

## Governance note — unresolved decision

The repository constitution does not formally adopt OpenSpec. Files under `openspec/changes/` are OpenSpec-compatible, non-runtime authority artifacts; they require no OpenSpec CLI. ADR 0033 supersedes ADR 0032's optional-persistence portions without changing this adoption boundary.

No runtime, hook, MCP, SDK, dependency, installer, alias, state store, or automatic migration is added. Do not infer live discovery or routing from static files; execute the isolated smoke plan separately.
