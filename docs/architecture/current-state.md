# Current architecture

The product is a Cursor-only static bundle described by `.cursor-plugin/plugin.json`: four agent Markdown files, five skill directories containing one Markdown file each, one command Markdown file, and one always-applied MDC rule. No repository JavaScript, package dependency, service, hook, MCP server, installer, or build artifact participates in installed behavior.

Context quality and parent-context preservation are the optimization function. The top-level main Agent is the sole orchestrator and synthesizer. It retains intent, decisions, native Plan/Todo state, concise specialist findings, binary acceptance criteria, returned evidence, agent IDs, and reviewer verdicts. It delegates broad repository reads/searches to built-in Explore rather than absorbing their output.

Three custom specialists are read-only: researcher, strategist, and independent reviewer. One `curiosity-implementer` is writable and is the sole source editor for one bounded assignment. Each role requires its method skill; the implementer requires implementation discipline and architecture awareness. Skill requirements are semantic because Cursor provides no documented programmatic attachment in these assets. All agents report directly to main, none delegates, and only one writable implementer may exist at a time.

The same four-agent hierarchy implements three policy layers: AUTHORITY preserves orchestration/edit boundaries; CURIOSITY performs one bounded, value-sensitive challenge; EVIDENCE makes raw outputs and independent review control completion. Every substantive child result, including Explore, carries the canonical rule's compact receipt. Main gates progress, resumes the same ID for bounded repair or reconciliation, and never turns curiosity into autonomous follow-up. This is semantic protocol only; no host validator, hook, or state exists.

**Required semantic invariant:** main never edits project source or runs project-mutating shell commands. **Desired host enforcement / known limitation:** Cursor currently cannot deny main edits while allowing a writable child because children inherit the parent mode/tool envelope. Prompt compliance governs the boundary. Writable hierarchy stays in Agent mode; Plan Mode may precede it for human approval, while Ask/Plan cannot be expected to elevate a child.

Repository-only Bun tooling validates the pinned Cursor schema, surface shape, policy text, behavioral fixture schema, file safety, provenance, and secrets; Ajv and YAML are development dependencies only. Static fixtures do not prove live behavior. Historical architectures are isolated in `provenance/history/`. ADR 0030 controls role authority and composable expertise; ADRs 0027–0029 retain the Cursor-only, hierarchy, and curiosity foundations.
