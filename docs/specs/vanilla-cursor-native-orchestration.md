# Hierarchical context-preserving Cursor delivery

**Status:** Normative, accepted 2026-08-16; revised for 0.6.0.

## Authority and installed surface

Context quality and parent-context preservation are the optimization objective. Main orchestrates and synthesizes only; built-in Explore owns broad repository discovery; implementer solely writes; strategist, researcher, and reviewer remain read-only. All custom agents report directly to main and never delegate. The main no-edit invariant is semantic rather than host-enforced because children inherit the parent mode/tool envelope.

The manifest installs exactly four agents, five composable skills, `/curiosity-deliver-change`, and one always-applied `curiosity-delivery` rule. Assets are regular non-executable Markdown/MDC. There are no hooks, MCP, SDK, scripts, daemon, runtime loader, state store, installer, or aliases.

| Agent | Model preference | Required skills | Authority |
| --- | --- | --- | --- |
| strategist | `grok-4.6` | decision design | consequential architecture advice; read-only |
| researcher | `grok-4.6` | research evidence | external/version-sensitive evidence; read-only |
| implementer | `composer-2.5` | implementation discipline; architecture awareness | sole bounded writer; no architecture selection |
| reviewer | `claude-sonnet-5` | independent review | dual-pass verdict; read-only |

Skill requirements are semantic, not a claimed programmatic attachment. Model mappings are preferences; compatible fallback or failure remains host-dependent.

## Routing and handoffs

Main classifies `PROBE|BOUNDED|ARCHITECTURAL`, with escalation only. PROBE makes no persistent behavior change. BOUNDED work is local and reversible inside an approved boundary and routes implementer → fresh reviewer. ARCHITECTURAL work affects a consequential boundary and routes Explore → strategist plus optional researcher → explicit owner decision → implementer → reviewer.

Full writable/consequential handoffs include work class, required skills and why, authority granted/withheld, scope, repository-relative pointers, approved decisions, binary criteria, evidence requirements, and stop/escalate conditions. Compact Explore/routine-review handoffs include only relevant fields. Main retains decisions, pointers, capsules, IDs, and verdicts rather than raw logs or search history.

## Implementation and review

Before edits, implementer protects pre-existing dirty work and produces an Architecture Boundary Card. A disguised consequential boundary returns `OWNER_DECISION_REQUIRED`. Before behavior edits, it adds and executes focused intended RED; characterization and unrelated failures do not count. It makes the smallest root-cause patch, uses only project-supported checks, and performs a final allowed-path audit. The implementation skill solely defines typed statuses, reason codes, and `EVIDENCE_CAPSULE`.

Reviewer first checks criteria/spec compliance, then correctness, maintainability, tests, security, and boundaries. Evidence origins distinguish independently executed checks from audited evidence. The rule's canonical passing-verdict evidence gate governs `PASS|PASS_WITH_NOTES`; an unverified summary cannot establish PASS. Main launches a fresh initial reviewer, then resumes the same ID after corrections. It resumes the same implementer ID for repair. Maximum two review cycles; no third cycle.

Curiosity remains bounded and foundational. The rule solely defines the receipt and Parent Curiosity Gate. Raw evidence outranks Todo state. Static behavioral fixtures validate authored contract shape only and do not claim agent behavior.

## Dependency and runtime boundary

A target-project dependency requires explicit user approval of exact package, purpose, prod/dev scope, project-owned package-manager command, and expected manifest/lockfile changes. Never install globally, guess a manager, substitute `npx`, or use curl-pipe bootstrap; stop on ambiguity. Version 0.6.0 preserves historical relocation integrity, provenance, lockfile secret scanning, and the Cursor-only product boundary.
