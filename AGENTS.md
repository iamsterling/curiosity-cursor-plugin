# Repository Constitution

This public MIT repository contains the Cursor-only `@iamsterling/curiosity-cursor-plugin`.

- Preserve source attribution, historical records, and reproducible manifests in `provenance/`.
- Keep the installed surface at exactly four agents, five composable file-only skills, one command, and one always-applied rule.
- REQUIRED SEMANTIC INVARIANT: foundational delivery has AUTHORITY (top-level main only orchestrates/synthesizes; the bounded implementer solely edits), CURIOSITY (bounded value-sensitive assumption challenge under the canonical rule), and EVIDENCE (raw evidence plus independent review controls completion). Researcher, strategist, and reviewer remain read-only; no specialist delegates.
- DESIRED HOST ENFORCEMENT is not currently available for the main no-edit boundary because Cursor children inherit the parent mode/tool envelope. Stay in Agent mode for writable hierarchy and never claim the prompt-governed invariant is capability enforcement.
- Installed assets stay regular, non-symlink, non-executable Markdown/MDC and require only Cursor.
- Add no hooks, MCP, installer, SDK, package runtime, executable plugin asset, state store, or compatibility alias.
- A target-project dependency requires explicit user approval of the exact package, purpose, prod/dev scope, project-owned command, and expected manifest/lockfile changes. Never install globally, guess a manager, substitute npx, or use curl-pipe bootstrap; stop on ambiguity and record output, status, diff, and verification.
- Never commit credentials, runtime state, logs, generated caches, dependencies, or global user configuration.
- Do not publish, release, install globally, or cut over from this repository without separate review.
- Before behavior changes, add a failing focused test; run `bun run verify` before handoff.
